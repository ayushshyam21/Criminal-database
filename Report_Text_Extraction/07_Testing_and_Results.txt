### EXPLAIN Benchmark Results

We evaluated our indexing decisions by analyzing query execution plans with MySQL EXPLAIN before and after adding the indexes. Filtering public_crime_incidents by district ("001") and date range without an index forced MySQL into a full table scan (type: ALL) that checked all ~50,000 rows. With our composite index idx_pci_district enabled, the access type changed to range/ref and the examined rows dropped to fewer than 500. This resulted in an over 95% reduction in scanned rows, reducing query execution time from roughly 160ms down to under 5ms.


### Chapter 14: Results & Discussion

Designing, implementing, and testing our system provided several practical insights into database development and application security:

14.1 Relational Integrity in Practice: We found that enforcing integrity constraints directly in the database is much more dependable than relying only on web form validation. For example, our check constraint chk_cases_closure_consistency prevented cases from being marked "Closed" without a closing date, while virtual generated keys reliably blocked duplicate active assignments even during concurrent requests.

14.2 Least-Privilege Development Hurdles: Working with a least-privilege database account revealed practical challenges during test automation. In our citizen test suite, our cleanup code initially attempted to delete test accounts using crimedb_app, which immediately failed with MySQL Error 1142 because DELETE permissions were intentionally revoked. We solved this by generating unique UUID emails for test records instead of trying to delete them, which also served as proof that our database permissions were working properly.

14.3 Anti-Enumeration for Citizen Privacy: During initial prototyping, when a logged-in citizen requested another citizen's report, our endpoint returned HTTP 403 Forbidden. Although this blocked unauthorized access, it inadvertently confirmed that the requested report ID existed. We changed the response to HTTP 404 Not Found, eliminating the information leak and protecting citizens from automated tracking ID probing.

14.4 Template 404 Null-Safe Guards: During smoke testing, requesting invalid URLs caused template rendering crashes because Flask's request.endpoint was None on 404 pages. We fixed this by adding null checks ({% if request.endpoint and 'cases' in request.endpoint %}) across base.html, allowing custom error pages to display cleanly without triggering an unhandled 500 server error.
