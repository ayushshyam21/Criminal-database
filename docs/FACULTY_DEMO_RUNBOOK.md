# Faculty Demonstration Runbook & Operational Verification
**Project:** Criminal Case Management & Crime Analytics Relational DBMS  
**Target Environment:** Localhost (Windows 11 / Windows Server)  
**Database Server:** MySQL Community Server 9.7.1 on `127.0.0.1:3306` (`crime_db`)  
**Backend Application:** Python 3.14 / Flask 3.1.2 / SQLAlchemy 2.0.44 / PyMySQL 1.1.2  
**Frontend Framework:** Bootstrap 5.3.3 / Chart.js 4.4.1 / Jinja2  
**Total Base Relations:** 14 Normalized Tables (BCNF)  
**Automated Verification:** 35 Automated Pytest Cases (100% Pass Rate) + 24 Smoke Test Checks

## 1. Quick Start Commands

## 4. Timed 7-Minute Faculty Demonstration Sequence

### Minute 0:00 – 1:00: Architecture & Dual-Account Security Barrier
1. Open PowerShell and run the runtime least-privilege security check:
   ```powershell
   python scripts/test_db_connection.py
   ```
2. Explain to faculty:
   - **`crimedb_admin`**: Used exclusively for schema migrations, batch imports, and owns `DEFINER` triggers.
   - **`crimedb_app`**: Runtime account used by Flask. Has **zero write access** to `audit_log` and `evidence_custody_log`, **read-only access** to Chicago public crime data, and **zero DDL privileges** (`DROP TABLE` denied).
   - Point out that audit ledgers are truly tamper-proof because even a complete application compromise cannot modify historical custody records.

### Minute 1:00 – 2:30: Multi-Level Security (MLS) & Need-to-Know Enforcement
1. Open browser at `http://127.0.0.1:5000/login`.
2. **Demonstrate High Clearance (Admin):**
   - Log in as `admin_sys` / `DemoPass123!`.
   - Note the red **RESTRICTED** badge next to Chief Eleanor Vance's name in the top navigation.
   - Navigate to `/cases` and open Case 9 (`CASE-2026-0009` — Homicide Investigation). Access is granted (**HTTP 200**).
3. **Demonstrate Discretionary Need-to-Know (Investigator):**
   - Log out, then log in as `investigator_hayes` / `DemoPass123!`.
   - Note the yellow **CONFIDENTIAL** badge.
   - Attempt to open Case 7 (`http://127.0.0.1:5000/cases/7` — Cyber Extortion).
   - **Result:** **HTTP 403 Forbidden** error page is rendered. Explain that although Detective Hayes possesses `CONFIDENTIAL` clearance, they lack an active operational assignment (`case_assignments.is_active = TRUE`) to Case 7, strictly enforcing the military-grade Need-to-Know principle.
4. **Demonstrate "No Read Up" Bell-LaPadula Property (Patrol Officer):**
   - Log out, then log in as `officer_carter` / `DemoPass123!`.
   - Note the blue **INTERNAL** badge.
   - In `/cases`, observe that RESTRICTED cases (like Case 9) are completely absent from the table.
   - Direct-probe `http://127.0.0.1:5000/cases/9`.
   - **Result:** **HTTP 403 Forbidden** error page. Demonstrates that query pruning and URL direct access both strictly enforce security.

### Minute 2:30 – 3:30: Admin Personnel & Clearance Governance
1. Log in as `admin_sys` / `DemoPass123!`.
2. Click **Staff Clearances** (`/admin/staff`) in the navigation bar.
3. Show the interactive clearance table listing all 7 department personnel.
4. Locate Detective Kowalski (currently `INTERNAL`). Change their clearance to **`CONFIDENTIAL`** and click **Update**.
5. Show the instant success alert: *"Updated personnel clearance for Det. David Kowalski: INTERNAL -> CONFIDENTIAL."*
6. Explain that this enables dynamic assignment workflows while maintaining an administrative audit trail.

### Minute 3:30 – 4:45: Decoupled Public Citizen Portal
1. Open an Incognito window (or navigate to `/citizen/login`).
2. Log in as demo citizen `citizen.jane@example.com` / `Citizen123!`.
3. View the **Citizen Dashboard** with summary metric cards and existing demo submissions:
   - `CR-2026-00001` (Lost Property — Under Review)
   - `CR-2026-00002` (Vandalism — Submitted)
4. Click **File New Incident Report** (`/citizen/reports/new`).
5. Fill out a sample report:
   - Category: `Lost Property`
   - Incident Date: Today's date
   - Location: `Union Station Main Concourse`
   - Title: `Lost Black Leather Wallet`
   - Description: `Misplaced black bi-fold wallet containing student ID near ticketing counter.`
6. Submit the report. Show the auto-generated tracking reference: **`CR-2026-XXXXX`**.
7. **Demonstrate Anti-Enumeration Privacy Defense:**
   - In the URL, change the report ID to `999` or probe another citizen's report ID.
   - Show that the server returns **HTTP 404 Not Found** (instead of 403 Forbidden), preventing malicious attackers from confirming valid tracking IDs through status code enumeration.
8. Highlight domain isolation: Explain that citizen demo reports carry `is_demo_submission = TRUE` and are stored in `citizen_reports`, never contaminating police criminal cases or Chicago open statistics.

### Minute 4:45 – 5:45: Stored Procedures & Trigger-Enforced Custody Chain
1. Switch back to the police staff window (`admin_sys`).
2. Navigate to `/cases/5` (`CASE-2026-0005`):

   - Show personnel assignment executed via stored procedure **`sp_assign_case`**, which atomically advances case status to `'Under Investigation'` and prevents duplicate active lead investigators.

### Minute 5:45 – 6:30: Chicago Crime Analytics & Query Optimization (EXPLAIN)

## 6. Known Issues, Limitations & Workarounds

1. **Diagram PNG Files vs 14-Table Documentation:**
   - **Condition:** The rendered diagram exports `docs/erd.png` and `docs/eerd.png` reflect the original 12-table base schema created before adding `citizens` and `citizen_reports`.
   - **Workaround:** The written technical documentation (`docs/PROJECT_REPORT.md`, `docs/PRESENTATION.md`, `docs/data_dictionary.md`, and `docs/relational_schema.md`) fully documents all 14 tables, their functional dependencies, and referential integrity. When presenting diagrams, direct faculty attention to the updated Mermaid ERD in `docs/PROJECT_REPORT.md`.
2. **Citizen Account Deletion Prevention:**
   - **Condition:** In adherence to least-privilege principles, `crimedb_app` has `SELECT, INSERT, UPDATE` on `citizens` and `citizen_reports`, but has **NO direct DELETE grant**.
   - **Workaround:** Test scripts generate unique email addresses (`uuid.uuid4()`) rather than deleting and recreating records, preserving database integrity.
3. **Chicago Open Data API Rate Limiting:**
   - **Condition:** Live Socrata Open Data imports require public internet connectivity.
   - **Workaround:** Over 50,000 real Chicago crime records are pre-ingested into `public_crime_incidents` in MySQL, ensuring the application remains 100% functional and demonstrable even completely offline.
4. **404 Route Endpoint Safety:**
   - **Condition:** In templates, accessing `request.endpoint` when an invalid URL is queried previously evaluated to `None`.
   - **Workaround:** Resolved in `app/templates/base.html` with explicit `{% if request.endpoint and 'cases' in request.endpoint %}` guards. Verified across all routes.
